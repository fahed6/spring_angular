================================================================================
  1. PROJECT OVERVIEW
================================================================================

This is a web-based management system for a driving school (Auto École).
It allows two types of users to manage the school's operations:

  ADMIN  — Full access to everything: students, users, planning, payments,
            progress tracking, and analytics dashboards.

  STAFF  — Operational access: view/manage students, schedule sessions,
            track progress, and record payments. No user management.

The system is split into two completely separate projects:
  - Backend  : Spring Boot REST API (serves JSON, no HTML)
  - Frontend : Angular Single-Page Application (consumes the API)

They communicate over HTTP on localhost (backend on port 8080, frontend on 4200).

--- spring-boot-starter-webmvc ---
  WHAT: Provides the web layer — HTTP server (embedded Tomcat), @RestController,
        @RequestMapping, ResponseEntity, etc.
  WHY : This is the standard way to build REST APIs in Spring Boot. "webmvc"
        uses the traditional Servlet model (synchronous/blocking), which is
        simpler than reactive (WebFlux) and appropriate for this project.

--- spring-boot-starter-data-jpa ---
  WHAT: Provides JPA (Java Persistence API) via Hibernate ORM, plus Spring Data
        repositories (JpaRepository, derived query methods).
  WHY : Instead of writing raw SQL, we define entity classes and Spring
        automatically generates the SQL. Repository methods like
        `countByStatus("ACTIVE")` are derived from the method name.

--- postgresql (runtime scope) ---
  WHAT: The JDBC driver for PostgreSQL database.
  WHY : Runtime-only because it's only needed when the app actually runs,
        not for compilation. PostgreSQL is a production-grade open-source
        relational database.

--- spring-boot-starter-security ---
  WHAT: Spring Security framework — handles authentication, authorization,
        CORS, CSRF, filter chains.
  WHY : Industry standard for securing Spring applications. Provides the
        SecurityFilterChain, PasswordEncoder, and the infrastructure to
        plug in JWT validation.

--- jjwt-api + jjwt-impl + jjwt-jackson (version 0.12.6) ---
  WHAT: JJWT (Java JWT) library for creating and validating JSON Web Tokens.
        - jjwt-api    : compile-time dependency (the interfaces)
        - jjwt-impl   : runtime implementation (runtime scope)
        - jjwt-jackson : JSON serialization support for JWT claims (runtime scope)
  WHY : JWTs are the standard for stateless authentication in REST APIs.
        The token contains the user's email and role, is signed with HMAC-SHA256,
        and cannot be tampered with without knowing the secret key.

--- spring-boot-starter-webmvc-test (test scope) ---
  WHAT: Testing utilities for Spring MVC (MockMvc, @WebMvcTest, etc.)
  WHY : Allows testing controllers without starting a real server.

  5. BACKEND — SECURITY SYSTEM (JWT + SPRING SECURITY)
================================================================================

HOW JWT AUTHENTICATION WORKS — Step by Step:

STEP 1 — LOGIN:
  - User sends POST /api/auth/login with { email, password }
  - AuthService loads the user from DB, verifies password with BCrypt
  - If valid → JwtUtil generates a signed token containing:
      · subject   = user's email
      · claim     = role ("ADMIN" or "STAFF")
      · issuedAt  = now
      · expiration = now + 86400000ms (24 hours)
      · signature  = HMAC-SHA256 using secret key
  - Token is returned to the frontend in LoginResponse

STEP 2 — EVERY SUBSEQUENT REQUEST:
  - Frontend attaches the token to every HTTP request:
      Authorization: Bearer eyJhbGciOiJIUzI1NiJ9...
  - JwtFilter (extends OncePerRequestFilter) intercepts every request:
      · Reads the Authorization header
      · Strips the "Bearer " prefix
      · Calls JwtUtil.isValid() — verifies signature & expiry
      · Calls JwtUtil.extractEmail() and JwtUtil.extractRole()
      · Creates a UsernamePasswordAuthenticationToken with
        SimpleGrantedAuthority("ROLE_ADMIN") or ("ROLE_STAFF")
      · Puts it in SecurityContextHolder — Spring now knows who this is

STEP 3 — AUTHORIZATION:
  - SecurityConfig defines access rules:
      /api/auth/**    → permitAll()   (no token required)
      /api/admin/**   → hasRole("ADMIN")
      /api/staff/**   → hasAnyRole("ADMIN", "STAFF")
  - Spring Security checks the SecurityContextHolder against these rules
  - If unauthorized → 403 Forbidden is returned automatically

PASSWORD HASHING:
  - BCryptPasswordEncoder hashes passwords (one-way, salted, work factor 10)
  - Raw passwords are never stored in the database
  - encoder.matches(rawPassword, storedHash) is used to verify login

CORS:
  - Cross-Origin Resource Sharing configured to allow requests from
    http://localhost:4200 (Angular dev server)
  - Allowed methods: GET, POST, PUT, DELETE, OPTIONS
  - OPTIONS preflight requests are automatically handled

ENTITY: Planning (table: planning)
  - id (BIGINT, auto-generated PK)

  - type (VARCHAR 10) — CODE | CONDUITE
  - status (VARCHAR 15, default "SCHEDULED") — SCHEDULED | COMPLETED | CANCELLED

  - created_at (TIMESTAMP)

ENTITY: Progress (table: progress)
  - id (BIGINT, auto-generated PK)
  - student_id (FK → students.id)
  - theory_score (INTEGER, 0-100)
  - practical_score (INTEGER, 0-100)
  - sessions_completed (INTEGER)
  - sessions_total (INTEGER)
  - notes (TEXT)
  - updated_at (TIMESTAMP)

ENTITY: Payment (table: payments)
  - id (BIGINT, auto-generated PK)
  - student_id (FK → students.id)
  - amount (DECIMAL 10,2)
  - paid_at (DATE, default today)
  - method (VARCHAR 10) — CASH | CARD | TRANSFER
  - status (VARCHAR 10, default "PAID") — PAID | PENDING | PARTIAL
  - description (TEXT)
  - recorded_by (FK → users.id)
  - created_at (TIMESTAMP)

JPA ANNOTATIONS:
  @Entity           — marks class as a database table
  @Table(name=)     — specifies table name
  @Id               — primary key
  @GeneratedValue   — auto-increment
  @Column           — column configuration (nullable, length, unique)
  @ManyToOne        — many students can be registered by one user
  @JoinColumn       — defines the FK column name
  @Enumerated(EnumType.STRING) — stores enum as string, not integer

LAZY vs EAGER loading:
  All @ManyToOne relationships use FetchType.LAZY — the related entity is
  only loaded from the database when you actually access it. This prevents
  the "N+1 query problem" and keeps queries fast.

  7. BACKEND — DTOs (DATA TRANSFER OBJECTS) — JAVA RECORDS
================================================================================

WHY DTOs?
  We never expose JPA entities directly to the API. Entities have:
  - Lazy-loaded relationships (cause serialization errors)
  - Password hashes (security leak)
  - Internal fields the client doesn't need
  DTOs are simple data containers — exactly what the API sends/receives.

WHY JAVA RECORDS?
  Java 21 records are immutable data carriers. Instead of:
    public class LoginResponse {
      private String token;
      private String role;
      // constructor, getters, equals, hashCode, toString...
    }
  We write:
    public record LoginResponse(String token, String role, String fullName) {}
  The compiler generates everything automatically. Records are:
  - Immutable (fields are final)
  - Auto-generate constructor, getters (token(), role()), equals, hashCode, toString
  - Perfect for DTOs that only carry data

IMPORTANT — Record accessor syntax:
  In a record, you access fields with no "get" prefix:
    record.token()   not   record.getToken()
  This affects how Jackson serializes them to JSON — field names map directly.

KEY DTOs:
  LoginRequest   — { String email, String password }
  LoginResponse  — { String token, String role, String fullName }
  StudentRequest — { String firstName, lastName, email, phone, address,
                     String dateOfBirth, String status, Long registeredBy }
  StudentResponse — same fields + id, registeredAt
  DashboardResponse — record with 13 fields: counts, lists for charts
  StaffDashboardResponse — record with 10 fields for staff charts

================================================================================
  8. BACKEND — REPOSITORY LAYER
================================================================================

Spring Data JPA repositories extend JpaRepository<Entity, IdType>.
This gives us CRUD methods for free: save(), findById(), findAll(), delete().

CUSTOM DERIVED QUERIES (method name = SQL query):
  Spring reads the method name and generates the SQL automatically.

  StudentRepository:
    countByStatus(String status)
    → SELECT COUNT(*) FROM students WHERE status = ?

    countByRegisteredAtAfter(LocalDateTime date)
    → SELECT COUNT(*) FROM students WHERE registered_at > ?

    countByRegisteredAtBetween(LocalDateTime from, LocalDateTime to)
    → SELECT COUNT(*) FROM students WHERE registered_at BETWEEN ? AND ?

  PlanningRepository:
    countByStatus(String status)
    → SELECT COUNT(*) FROM planning WHERE status = ?

    countByType(String type)
    → SELECT COUNT(*) FROM planning WHERE type = ?

  PaymentRepository:
    countByStatus(String status)
    → SELECT COUNT(*) FROM payments WHERE status = ?

    countByMethod(String method)
    → SELECT COUNT(*) FROM payments WHERE method = ?

  UserRepository:
    findByEmail(String email) → Optional<User>
    → SELECT * FROM users WHERE email = ?

HOW DERIVED QUERIES WORK:
  Spring parses the method name:
  countBy   → SELECT COUNT(*)
  findBy    → SELECT *
  Status    → WHERE status = ?
  After     → WHERE field > ?
  Between   → WHERE field BETWEEN ? AND ?
  The field names must exactly match entity field names.

  9. BACKEND — SERVICE LAYER

Services contain the business logic. They sit between controllers and repos.

AuthService:
  - Loads user by email from UserRepository
  - Verifies password: passwordEncoder.matches(raw, hash)
  - If valid: calls JwtUtil.generateToken(email, role)
  - Returns LoginResponse record

StudentService:
  - findAll() → returns List<StudentResponse>
  - Maps each Student entity to a StudentResponse (DTO)
  - save(StudentRequest) → creates Student entity, sets fields, saves
  - update(id, StudentRequest) → loads, updates fields, saves
  - delete(id) → studentRepository.deleteById(id)

DashboardService (admin):
  - Calls multiple repositories to gather stats
  - Computes 6-month enrollment trend using YearMonth API:
      for i = 5 down to 0:
        ym = YearMonth.now().minusMonths(i)
        from = first day of that month at midnight
        to = last day of that month at 23:59:59
        count students registered between from and to
        label = month name in French (TextStyle.SHORT, Locale.FRENCH)
  - Returns DashboardResponse record with all 13 fields

StaffDashboardService:
  - Similar but with staff-relevant stats (no user counts)
  - Returns StaffDashboardResponse record with 10 fields

Controllers receive HTTP requests and return HTTP responses.

ANNOTATIONS:
  @RestController  — combines @Controller + @ResponseBody (returns JSON)
  @RequestMapping  — base URL prefix for all methods in the class
  @GetMapping      — handles HTTP GET
  @PostMapping     — handles HTTP POST
  @PutMapping      — handles HTTP PUT
  @DeleteMapping   — handles HTTP DELETE
  @PathVariable    — extracts {id} from URL path
  @RequestBody     — parses JSON body into a Java object

RESPONSE PATTERN:
  All controllers return ResponseEntity<T>:
    ResponseEntity.ok(data)          → 200 OK with data
    ResponseEntity.noContent().build() → 204 No Content (for deletes)
    ResponseEntity.notFound().build()  → 404 Not Found

SECURITY INTEGRATION:
  The @RequestMapping prefix determines who can access it:
    /api/admin/** → only ADMIN
    /api/staff/** → ADMIN or STAFF
    /api/auth/**  → everyone

  To get the currently logged-in user in a controller:
    @RequestHeader("Authorization") String authHeader
    String token = authHeader.substring(7); // strip "Bearer "
    String email = jwtUtil.extractEmail(token);
    User user = userRepository.findByEmail(email).orElseThrow();

================================================================================
  11. BACKEND — CORE LOGIC EXPLAINED
================================================================================

WHY STATELESS? (No sessions)
  REST APIs should be stateless — every request must be self-contained.
  The server stores no session state between requests. This makes the API
  scalable (any server instance can handle any request) and cacheable.

HOW BCrypt WORKS:
  BCrypt is a one-way hashing function. It adds a random "salt" before
  hashing, so the same password produces different hashes each time.
  You cannot reverse a BCrypt hash — you can only check a plaintext
  password against a stored hash using matches().

HOW YearMonth WORKS (for charts):
  YearMonth represents a specific year+month (e.g., "2026-01").
  .minusMonths(i) goes back i months.
  .atDay(1) = first day of that month.
  .atEndOfMonth() = last day (handles different month lengths).
  .getMonth().getDisplayName(TextStyle.SHORT, Locale.FRENCH)
    converts month number to French short name ("janv.", "févr.", etc.)

GLOBAL EXCEPTION HANDLER:
  @RestControllerAdvice intercepts exceptions thrown anywhere in the app.
  Returns structured JSON error responses instead of Spring's default HTML.

  14. FRONTEND — ANGULAR CONCEPTS USED
================================================================================

STANDALONE COMPONENTS (Angular 14+, standard in Angular 19):
  Each component is self-contained — it declares its own imports.
  No NgModules needed. Example:
    @Component({
      selector: 'app-login',
      standalone: true,
      imports: [ReactiveFormsModule, NgIf, NgFor],  ← explicit imports
      templateUrl: './login.component.html'
    })
  The imports array replaces what used to go in @NgModule imports.

LAZY LOADING:
  Routes use loadComponent() with dynamic import() to only load a component's
  JavaScript when that route is first visited:
    { path: 'dashboard', loadComponent: () =>
        import('./admin/dashboard/dashboard.component')
        .then(m => m.DashboardComponent) }
  This keeps the initial bundle small and app loads faster.

DEPENDENCY INJECTION:
  Angular's DI system provides service instances automatically.
  Two styles are used:
    private svc = inject(AuthService);    ← modern inject() function
    constructor(private svc: AuthService) ← traditional constructor injection
  Both work identically. The inject() style is preferred in Angular 19.

REACTIVE FORMS:
  Used for ALL forms in the project (never template-driven forms).
    this.form = new FormGroup({
      email:    new FormControl('', [Validators.required, Validators.email]),
      password: new FormControl('', Validators.required)
    });
  In template: [formGroup]="form", formControlName="email"
  Validation: form.get('email')?.invalid && form.get('email')?.touched

OBSERVABLES + subscribe():
  HttpClient returns Observable<T>. To get the data:
    this.svc.getStudents().subscribe(data => {
      this.students = data;
    });
  Observables are lazy — they don't execute until subscribed.

*ngIf / *ngFor (structural directives):
  *ngIf="condition"   → conditionally renders element
  *ngFor="let item of list"  → repeats element for each item in array
  These must be imported: imports: [NgIf, NgFor]

TWO-WAY BINDING:
  [(ngModel)] is used for simple select dropdowns (requires FormsModule).
  Most form state is managed by ReactiveFormsModule FormGroup.

routerLink / routerLinkActive:
  routerLink="dashboard"       → navigate to sibling route on click
  routerLinkActive="css-class" → adds class when that route is active (for nav highlighting)

@ViewChild:
  Gets a reference to a DOM element or child component from TypeScript.
  Used for Chart.js canvas elements:
    @ViewChild('chartSessions') chartSessionsRef!: ElementRef<HTMLCanvasElement>;
  The ! (definite assignment assertion) tells TypeScript "this will be set before use".

OnInit / OnDestroy lifecycle hooks:
  ngOnInit()    → called after component is initialized (load data here)
  ngOnDestroy() → called before component is removed (cleanup here, destroy charts)

isPlatformBrowser():
  Angular 19 supports SSR (server-side rendering in Node.js).
  Browser APIs (window, document, canvas) don't exist on Node.js.
  Guard: if (isPlatformBrowser(this.platformId)) { /* browser-only code */ }
  Injected via: private platformId = inject(PLATFORM_ID);

  15. FRONTEND — AUTHENTICATION FLOW
================================================================================

1. User visits / → redirects to /login
2. User submits login form
3. LoginComponent calls AuthService.login({ email, password })
4. AuthService sends POST to http://localhost:8080/api/auth/login
5. Backend returns { token, role, fullName }
6. AuthService stores token in localStorage:
     localStorage.setItem('token', response.token)
     localStorage.setItem('role', response.role)
     localStorage.setItem('fullName', response.fullName)
7. AuthService navigates based on role:
     ADMIN → /admin/dashboard
     STAFF → /staff/dashboard
8. On subsequent navigation, guards check role:
     adminGuard → reads localStorage role, allows ADMIN only
     staffGuard → reads localStorage role, allows ADMIN or STAFF
9. HttpInterceptor attaches token to every request:
     Authorization: Bearer <token>
10. Logout: clears localStorage, navigates back to /login

================================================================================
  17. FRONTEND — GUARDS (ROUTE PROTECTION)
================================================================================

File: core/guards/auth.guard.ts

Guards are functions that return true (allow navigation) or false / UrlTree
(block navigation, possibly redirect).

  export const adminGuard: CanActivateFn = () => {
    const auth = inject(AuthService);
    const router = inject(Router);
    if (auth.getRole() === 'ADMIN') return true;
    return router.createUrlTree(['/login']);
  };

  export const staffGuard: CanActivateFn = () => {
    const role = inject(AuthService).getRole();
    const router = inject(Router);
    if (role === 'ADMIN' || role === 'STAFF') return true;
    return router.createUrlTree(['/login']);
  };

HOW THEY'RE USED in app.routes.ts:
  { path: 'admin', canActivate: [adminGuard], ... }
  { path: 'staff', canActivate: [staffGuard], ... }

Angular calls the guard function before rendering the route's component.
If the guard returns false or a UrlTree, the component never loads.

  19. FRONTEND — CHARTS (CHART.JS)

Library: chart.js v4.5.1 (no Angular wrapper — used directly)

SETUP:
  import { Chart, registerables } from 'chart.js';
  Chart.register(...registerables);  // registers all chart types globally

THE PROBLEM WITH SSR + CANVAS:
  Angular 19 renders components on Node.js (server-side) as well as in the
  browser. Canvas operations only work in the browser. Solution:
    if (isPlatformBrowser(this.platformId)) {
      setTimeout(() => this.renderCharts(), 0);
    }
  The setTimeout(0) ensures Angular has finished re-rendering the *ngIf block
  (which shows canvases only when data is loaded) before we try to use them.

CHART TYPES USED:

  'bar'       — vertical bar chart
  'bar' with indexAxis: 'y' — horizontal bar chart

CLEANUP:
  Charts must be destroyed when the component is destroyed, otherwise
  Chart.js throws "Canvas already in use" errors on re-navigation:
    ngOnDestroy(): void {
      this.charts.forEach(c => c.destroy());
    }

  25. KEY DESIGN DECISIONS (FOR PROFESSOR QUESTIONS)
================================================================================

Q: Why use Java Records for DTOs?
A: Records are immutable data carriers introduced in Java 16 (standard in 21).
   They auto-generate constructor, accessors (field(), not getField()), equals,
   hashCode, and toString. Perfect for DTOs that only need to carry data.
   Avoids boilerplate. The professor specifically requested records.

Q: Why separate DTOs from Entities?
A: Entities are JPA-managed objects tied to the database. Exposing them
   directly in the API causes: serialization of lazy-loaded proxies (LazyInit
   errors), exposure of sensitive fields (password hashes), and tight coupling.
   DTOs are a clean interface between layers.

Q: Why JWT instead of sessions?
A: REST APIs should be stateless. JWT carries all auth info in the token itself.
   No server-side session storage needed. Scales horizontally (any server can
   validate any token). The token is signed — if tampered, validation fails.

Q: Why Spring Security + BCrypt?
A: Industry standard. BCrypt is specifically designed for password hashing —
   it's slow by design (work factor) which makes brute-force attacks expensive.
   Never store plain-text passwords.

Q: Why standalone components in Angular 19?
A: Angular 19 uses standalone components as the default. They're simpler —
   no need for NgModules. Each component explicitly declares what it imports.
   Better tree-shaking (unused code is not bundled).

Q: Why lazy loading routes?
A: With lazy loading, each route's component code is only downloaded when that
   route is first visited. This reduces initial bundle size and speeds up first
   page load. Essential for large applications.

Q: Why isPlatformBrowser() guards?
A: Angular 19 includes SSR (server-side rendering). Some code runs in Node.js
   on the server, where browser APIs like Canvas don't exist. Guards prevent
   errors: if (isPlatformBrowser(this.platformId)) { /* canvas code */ }

Q: Why pure CSS instead of a framework?
A: The project uses a custom CSS design system inspired by SAP Fiori enterprise
   UI. CSS custom properties (variables) provide consistent theming. No
   framework dependency means no version conflicts and full control over styles.

Q: How does role-based access work end-to-end?
A: 1. Backend SecurityConfig rules: /api/admin/** = ADMIN only,
      /api/staff/** = ADMIN or STAFF.
   2. Angular Guards: adminGuard allows only ADMIN to reach /admin routes,
      staffGuard allows ADMIN or STAFF for /staff routes.
   3. Even if a user bypasses the frontend guard, the backend will reject
      the API call with 403 Forbidden. Defense in depth.

Q: What is the relationship between Admin and Staff access?
A: Admin has full access to everything. The /api/staff/** endpoints are
   accessible to both roles. In the Angular frontend, the admin layout also
   includes links to planning, progress, and payments pages (which reuse the
   same staff components). Admin simply has more routes available.

Q: Why use @ViewChild for Chart.js instead of a library?
A: chart.js is used directly to avoid adding extra dependencies (@types/chart.js,
   ng2-charts wrapper). @ViewChild gives direct access to the native canvas
   DOM element (nativeElement) which Chart.js requires. Simpler and more
   transparent than using a wrapper.

Q: What is the DataInitializer?
A: It implements CommandLineRunner, which Spring Boot calls after context starts.
   It checks if the users table is empty — if so, creates one ADMIN and one
   STAFF user with hashed passwords. This ensures the system is usable on first
   run without manual database seeding.
